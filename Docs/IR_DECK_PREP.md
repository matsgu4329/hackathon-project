## 1. 표지

**SkinClock(스킨클락)**
사용자의 생활 상황(귀가)과 실시간 날씨·자외선 정보를 반영해, 지금 해야 할 세안·스킨케어 루틴을 알려주는 상황 인지형 알림 서비스

> 팀명 / 발표일 / 팀원 정보는 팀에서 채워넣기 (§6 팀원소개 참고)

## 2. 기존 아이템 문제 제기 및 필요성

건강한 피부를 유지하기 위해 가장 중요한 것은 올바른 세안과 지속적인 기초 스킨케어 실천이다. 그러나 대다수의 스킨케어 초보자와 바쁜 현대인은 다음과 같은 문제에 직면해 있다.

**1. 고정 시간 알림의 비효율성과 실천율 저하**
기존 뷰티 및 알림 앱은 "오후 8시 세안"과 같이 매일 고정된 시간에 푸시 알림을 발송한다. 그러나 출퇴근, 야근, 약속 등으로 귀가 시간이 불규칙한 사용자는 밖에서 알림을 받아 무시하게 되고, 정작 귀가 후에는 피로감으로 인해 세안을 미루다 잠드는 악순환을 겪는다.

**2. 복잡한 환경 요인과 제품 사용 시점 판단의 어려움**
날씨(습도, 건조도)와 자외선(UV) 지수에 따라 필요한 스킨케어는 달라진다. 또한 레티놀, AHA/BHA 등 특정 성분은 자외선 반응성 때문에 취침 전에 사용해야 하거나, 각질 케어·팩 등은 2~3일 주기로 사용해야 함에도 초보자가 이를 매번 기억하고 적용하기는 번거롭다.

**3. 과도한 진단과 광고로 인한 피로감**
기존 서비스들은 지나치게 복잡한 피부 진단을 요구하거나 제품 구매 유도에 치중되어 있어, 정작 '지금 당장 내가 가진 제품으로 무엇을 해야 하는지'에 대한 직관적인 가이드를 주지 못한다.

**타겟 사용자**: 불규칙한 생활 패턴으로 피부 관리에 어려움을 겪는 18~35세 대학생 및 직장인. 특히 스킨케어 순서와 성분 사용법이 낯선 스킨케어 초보자가 1차 타깃.

## 3. 제품 소개 — 전면 · 핵심기능

### 서비스 소개

SkinClock은 사용자의 불규칙한 생활 패턴과 외부 환경, 보유 제품 특성을 결합하여 **'가장 적절한 순간'** 에 맞춤 루틴을 안내하는 상황 인지형 스킨케어 비서 서비스다.

- **상황 인지 기반 동적 알림**: 사용자의 귀가 시점을 인지하여 외출 후 피부에 쌓인 노폐물과 미세먼지를 즉시 씻어낼 수 있도록 타이밍에 맞춘 1차 세안 및 저녁 루틴 알림을 전달한다.
- **날씨·자외선 연동 실시간 루틴 튜닝**: 당일 기상 상태와 자외선 지수를 실시간 분석하여, 자외선이 강한 날에는 차단 중심 루틴을, 건조한 날에는 수분 보습 루틴을 자동으로 제안한다.
- **스마트 화장대(성분·주기 자동 관리)**: 사용자가 등록한 제품의 성분을 분석해 밤 전용 제품을 자동 분류하고, 주기성 제품의 다음 사용일을 스케줄링하여 초보자도 실패 없는 스킨케어 습관을 형성하도록 돕는다.

### 핵심 기능

**① 상황 인지형 귀가 감지 및 즉각 세안 알림 (Homecoming Trigger)** — ✅ 구현 완료
- **해결 방식**: 불규칙한 생활 패턴으로 인해 고정 시간 알림이 무시되던 문제를 해결하기 위해, 사용자의 '귀가 시점'을 인지하여 동작한다.
- **주요 기능**: 외출 후 귀가 이벤트가 감지(MVP에서는 모의 위치 시뮬레이터, 향후 지오펜싱 기반 자동 감지)되면 즉시 "외출 후 피부에 쌓인 노폐물을 씻어내세요"라는 브리핑 알림을 생성한다. 사용자가 피로감으로 세안을 미루기 전에 즉각 행동으로 옮길 수 있는 최적의 타이밍을 포착한다.

**② 날씨·자외선(UV) 연동 동적 루틴 최적화 (Environment-Adaptive Routine)** — ✅ 구현 완료
- **해결 방식**: 계절과 날씨 변화에 둔감한 스킨케어 초보자를 위해 실시간 환경 데이터를 루틴에 자동 반영한다.
- **주요 기능**: 기상청 및 Open-Meteo API와 연동하여 실시간 기온, 습도, 자외선 지수를 분석한다. 자외선 지수가 높은 날(UV 6 이상)에는 '자외선 차단제(SPF50+) 꼼꼼히 바르기' 안내를 루틴 상단에 동적으로 추가하고, 건조한 날에는 보습 중심의 가이드를 한 겹 더 얹어 제공한다.

**③ 성분 및 사용 주기 자동 스케줄링 화장대 (Smart Product Scheduler)** — ✅ 구현 완료
- **해결 방식**: 성분별 주의사항이나 제품별 사용 주기를 일일이 기억하기 어려운 문제를 시스템 자동화로 해결한다.
- **주요 기능**: 사용자가 보유한 화장품을 등록할 때 '레티놀', 'AHA/BHA' 등의 성분 태그를 선택하면 시스템이 이를 감지해 자동으로 취침 전 사용(NIGHT_ONLY)으로 분류하고 아침 추천에서 제외한다. 또한 마스크팩, 각질 제거제 등 주기성 제품은 이전 사용일을 기반으로 다음 권장 사용일을 자동 계산해 당일 루틴에 포함시킨다.

**④ Zero-Auth 간편 온보딩 및 습관 형성 트래킹 (Zero-Barrier Routine Tracker)** — ✅ 구현 완료
- **해결 방식**: 초기 진입 장벽과 기록의 번거로움을 최소화하여 지속적인 루틴 실천을 유도한다.
- **주요 기능**: 번거로운 회원가입 절차 없이 브라우저 고유 식별값(UUID) 기반으로 30초 만에 피부 타입과 외출 패턴 설정을 완료한다. 매일 안내받은 알림과 루틴을 완료 처리하면 히스토리 캘린더에 실천 기록이 축적되어 시각적인 성취감과 꾸준한 스킨케어 습관 형성을 돕는다(연속 달성일수·월간 완료율 표시).

## 4. 제품 소개 — 사용 흐름

실제로 검증된(Playwright E2E 테스트 통과) 사용자 흐름을 그대로 데모/슬라이드에 사용할 수 있다.

```
① 온보딩 (30초, 회원가입 없음)
   피부 타입 선택 → 외출 패턴·알림 희망 시각 설정 → 보유 중인 기본 제품 선택 → 완료
   └→ 자동으로 대시보드 이동

② 보유 제품 등록
   "레티놀 세럼" 등록 + 레티놀 성분 태그 선택
   └→ "자외선에 민감하므로 자동으로 밤 전용으로 분류됩니다" 즉시 안내

③ 하루의 시작 — 아침 브리핑
   당일 날씨·UV 자동 수집(1시간마다 갱신) → 오늘의 추천 루틴 생성
   UV가 높아지면(예: 11) → 실시간으로 "자외선 차단제 꼼꼼히 발라주세요 (UV 11)"로 루틴 갱신

④ 외출 후 — 귀가 감지
   귀가 이벤트 발생(MVP: 모의 입력) → 즉시 귀가 브리핑 알림 생성
   저녁 루틴에 등록된 레티놀 세럼(🌙 NIGHT_ONLY)이 자동으로 포함됨

⑤ 알림 확인 및 처리
   알림 센터에서 아침/귀가 브리핑을 완료·나중에·닫힘으로 처리

⑥ 습관 형성 확인
   이행 리포트에서 연속 달성일수, 이번 달 완료율, 캘린더 히트맵으로
   내 스킨케어 습관을 한눈에 확인
```

이 흐름은 "화면 하나씩 넘기는 데모"가 아니라, **환경(UV) 값을 실시간으로 바꾸면 추천 루틴이 그 자리에서 재계산되는 것**을 보여주는 것이 핵심 임팩트 포인트다 (아래 §5 결과 참고).

## 5. 제품 소개 — 결과

### 무엇을 실제로 만들었나

기획서(SPEC)에 정의된 6개 기능을 **백엔드·프론트엔드 모두 구현하고 실제 브라우저 환경에서 end-to-end로 동작 검증**했다.

| 기능 | 상태 |
|---|---|
| 보유 제품 및 사용 주기 관리 | ✅ 구현·검증 완료 |
| 최초 질문지 및 개인 루틴 설정 (온보딩) | ✅ 구현·검증 완료 |
| 개인화 일일 스킨케어 추천 | ✅ 구현·검증 완료 |
| 날씨·자외선 정보 시간별 수집 | ✅ 구현·검증 완료 |
| 아침·귀가 브리핑 알림 | ✅ 구현·검증 완료 |
| 웹 알림 확인 및 루틴 이행 기록 | ✅ 구현·검증 완료 |

- REST API **19개 엔드포인트**, 6개 도메인(프로필/제품/날씨/추천/알림/이행기록)
- 프론트엔드 화면 5개(`/onboarding`, `/products`, `/dashboard`, `/notifications`, `/history`) 전부 실제 백엔드 연동

### 기술적 완성도를 보여주는 근거

**실제 E2E 테스트로 배포 전 버그를 조기에 잡았다.** Playwright로 헤드리스 브라우저를 띄워 온보딩 → 제품 등록 → 추천 → 알림 → 이행기록까지 전 구간을 자동으로 클릭·검증하는 과정에서, 같은 사용자가 짧은 시간에 여러 요청을 보내면(예: 여러 탭, 빠른 재클릭) 서버 에러가 나는 **실제 동시성 버그 2건**을 발견해 수정했다.
- 오늘의 추천이 동시 요청 시 중복 생성되며 500 에러가 나던 문제
- 알림 중복 방지에 DB 제약이 없어 동시 요청 시 실제로 중복 알림이 생성되던 문제

두 버그 모두 데모 당일 실제로 재현될 수 있었던 문제로, **사전 통합 테스트(Phase 9)의 가치**를 보여주는 사례다. 백엔드 전체 테스트 스위트와 통합 테스트(MockMvc)도 통과 상태를 유지 중이다.

### 기술 스택 & 아키텍처

| 영역 | 스택 |
|---|---|
| 백엔드 | Java 25, Spring Boot 4.1.0, Spring Data JPA, H2(인메모리) |
| 프론트엔드 | Next.js 16, TypeScript, Tailwind CSS, TanStack Query, Zustand |
| 외부 연동 | 기상청(KMA) API, Open-Meteo API(폴백) |
| 배포 | Docker(멀티스테이지 빌드) 기반 Render 배포 준비 완료 |

- 회원가입 없이 **클라이언트 발급 UUID**로 사용자 식별 → 온보딩 마찰 최소화 (§3 핵심기능 ④와 연결)
- 백엔드는 **fat jar**, 프론트엔드는 **정적 export**로 빌드 → 빌드는 한 번, 실행은 최소 조건(JRE/브라우저)으로 가능

## 7. 로드맵

### Phase 1 — MVP 검증 및 초기 유저 확보 (현재)
Zero-Auth 기반의 웹 프로토타입으로 초기 진입 장벽을 없애고, 상황 인지 알림(귀가/자외선)을 통한 일일 활성 사용자(DAU) 및 루틴 실천율 데이터를 검증한다.

### Phase 2 — 모바일 PWA 및 지오펜싱(Geofencing) 자동화
모바일 웹 PWA 및 네이티브 앱 전환을 통해 백그라운드 지오펜싱(집 반경 100m 진입 시 자동 감지)과 시스템 레벨 웹 푸시 알림을 구현하여 사용자 개입 없는 완벽한 자동화를 달성한다.

### Phase 3 — 스마트홈 IoT 및 생태계 확장
스마트 도어락, AI 스피커(구글 홈, 카카오미니 등)와의 연동을 통해 현관문을 열고 들어오는 순간 음성으로 귀가 세안을 브리핑하는 올인원 스마트 라이프케어 플랫폼으로 확장한다.

### 로드맵과 함께 정리해 둘 기술 부채 / 리스크

| 항목 | 현황 |
|---|---|
| H2 인메모리 DB → 영속 DB(PostgreSQL 등) 전환 | 로드맵 Phase 2 이전 필수 (현재는 서버 재시작 시 데이터 소실) |
| 웹 푸시 3단계 폴백 완성 | 인앱 알림 목록은 완비, OS 네이티브 푸시는 미완 |
| 실제 GPS/지오펜싱 기반 귀가 감지 | 현재 모의 입력 → Phase 2에서 실제 신호로 전환 예정 |
| 다중 지역 날씨 지원 | 현재 서울 고정 좌표 |
| KPI 계측 | `RoutineLog`/`Notification` 테이블에 필요한 원자료는 이미 있음 — 집계 쿼리·대시보드만 추가하면 측정 가능 |

## 부록 A. 시장성 및 비즈니스 모델 (Q&A 대비용, 목차엔 없음)

### 시장성 및 타겟 고객
- **급성장하는 뷰티테크 및 셀프케어 시장**: 최근 2030세대를 중심으로 '슬로에이징(Slow-aging)'과 성분 중심 스킨케어 관심도가 급증하고 있으며, 남성 그루밍 시장 또한 매년 두 자릿수 성장세를 보이고 있다.
- **실행 중심의 버티컬 서비스 니즈**: 기존 뷰티 플랫폼(화해, 올리브영 등)은 '제품 탐색 및 구매'에 집중되어 있어, 구매 이후 일상에서 '언제, 어떻게 꾸준히 바를 것인가'를 챙겨주는 라이프스타일 밀착형 뷰티 비서 서비스는 시장의 블루오션이다.

### 비즈니스 모델
- **스마트 재구매 및 뷰티 커머스 연동**: 제품 등록 일자와 사용 주기를 기반으로 '화장품 소진 예상 시점'을 예측해 적시에 리필·재구매 링크를 제공하는 제휴 커머스 수수료(Affiliate).
- **환경·날씨 맞춤형 브랜드 타깃 광고**: 자외선 위험일의 선케어 제품 추천, 환절기 고보습 앰플 프로모션 등 실시간 기상 데이터와 연계된 브랜드 네이티브 광고·샘플링 이벤트.
- **프리미엄 구독(SkinClock+)**: 피부과 시술 후 맞춤 다운타임 케어 루틴, 스마트홈(IoT) 연동 자동 알림 등 고도화 기능 제공.
