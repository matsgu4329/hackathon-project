# SkinClock(스킨클락) 프론트엔드(FE) 제품 기획서 (FE PRD)

---

## 1. 프론트엔드 개요 및 UX 전략

### 1.1 FE 핵심 목표

* **직관적인 상황 인지 UX**: 사용자가 복잡한 설정 없이도 현재 날씨, 자외선, 귀가 상태 등 '상황'에 맞춰 지금 해야 할 세안 및 기초 스킨케어를 즉시 인지하도록 최적화된 화면을 제공한다.
* **낮은 진입 장벽 (스킨케어 초보자 유저 케어)**: 긴 글 위주의 설명 대신 단계별 체크리스트, 직관적인 아이콘, 성분 주의 태그(예: 🌙 야간 전용)를 활용해 행동(Action) 중심의 UX를 구현한다.
* **해커톤 MVP 모의 테스트 환경 구현**: 실제 GPS 제약 및 백엔드 개발 상황에 의존하지 않고, 화면 상단 툴바를 통해 **[귀가 모의 입력], [자외선 강도 변경]** 등을 인터랙티브하게 테스트할 수 있는 프론트엔드 상태 시뮬레이터를 구축한다.

---

### 1.2 개발 환경 및 UX/UI 기술 스택 (가이드)

* **Target Device**: 모바일 웹 브라우저 우선 (Mobile-First Responsive Layout, Web App Shell)
* **UI/UX Framework**: React / Next.js (Tailwind CSS, Lucide Icons, Framer Motion)
* **Client State Management**: React Query / TanStack Query (서버 데이터 캐싱 및 동기화), Zustand (클라이언트 모의 상태 및 UI 드로어/모달 제어)
* **Web Notification**: Service Worker 기반 Web Push API + 앱 내 토스트/드로어(In-App Notification Drawer) 폴백 지원

## 2. 정보 구조도 (Information Architecture) & 화면 경로

```
SkinClock Web App
├── 1. 온보딩 화면 (/onboarding)
│   └── 질문지 위저드 (피부 타입, 외출 패턴, 기본 루틴 등록)
├── 2. 메인 대시보드 (/dashboard)
│   ├── [상단] 날씨·자외선 정보 및 모의 상황 시뮬레이터 (귀가 버튼)
│   ├── [중단] 오늘의 추천 루틴 카테고리 (아침 / 귀가 후 / 취침 전)
│   └── [하단] 오늘의 루틴 이행 체크리스트
├── 3. 보유 제품 및 사용 주기 관리 (/products)
│   ├── 제품 목록 Grid/List & 성분 태그 필터
│   └── 제품 추가/수정 모달 (사용 단계, 주기, 성분 주의 안내)
├── 4. 알림 센터 (/notifications)
│   ├── 알림 목록 (아침 브리핑, 귀가 세안 알림, 주기성 제품 Remind)
│   └── 웹 푸시 권한 요청 획득 배너
└── 5. 루틴 이행 리포트 (/history)
    ├── 주간/월간 달력 (Streak & 달성률)
    └── 타임라인별 완료 기록

```

## 3. 화면별 상세 UI/UX 스펙

---

### 1) 온보딩 및 최초 질문지 화면 (`/onboarding`)

#### 화면 개요

스킨케어 초보자가 번거로움을 느끼지 않도록 3~4단계의 카드형 위저드(Wizard) 인터페이스로 구성한다.

```
+--------------------------------------------------------+
| [Step 1/3]  ■■■□□□□□                                 |
|                                                        |
|  Q1. 고객님의 피부 타입을 알려주세요.                     |
|                                                        |
|  [ 🌵 건성 ]      [ 💧 지성 ]     [ ⚖️ 복합성 ]        |
|  [ 🛡️ 민감성 ]   [ ❓ 잘 모르겠음 (기본값) ]            |
|                                                        |
|                                         [ 다음 단계 > ]|
+--------------------------------------------------------+

```

#### UI 컴포넌트 & UX 스펙

* **프로그레스 바 (Progress Bar)**: 상단에 현재 진척도(1/3, 2/3, 3/3)를 시각적으로 표시.
* **피부 타입 선택 칩 (Single Select Chips)**:
* 픽토그램 아이콘 + 직관적인 키워드 조합.
* '잘 모르겠음' 선택 시 보편적인 '중성/복합성' 기본 프로필 자동 지정.


* **외출 패턴 설정 섹션**:
* 외출 시간대 셀렉터 (예: Regular 09:00~18:00 vs Irregular 불규칙).
* 귀가 알림 수신 선호 시간 설정 휠(Picker) 또는 시간 선택 버튼.


* **기본 루틴 & 사용 중인 제품 간이 입력**:
* 자외선 차단제, 클렌징 폼, 수분크림 등 자주 쓰는 대표 카테고리를 체크박스 폼으로 빠르게 선택.


* **CTA 버튼**: `[설정 완료하고 추천 루틴 받기]` (입력 완료 시 대시보드로 리다이렉트).

### 2) 메인 대시보드 & 상황 인지 위젯 (`/dashboard`)

#### 화면 개요

접속 직후 현재 환경 정보(날씨, 자외선)와 내 상태에 맞는 '지금 해야 할 스킨케어 Action'을 가장 눈에 띄게 보여주는 뷰.

```
+--------------------------------------------------------+
| 📍 서울특별시 마포구                     [🔔 알림 3]   |
| ────────────────────────────────────────────────────── |
| [☀️ 자외선 높음 (UV 7)]  [🌧️ 습함 75%]  10:00 갱신   |
| 💡 "오늘처럼 자외선이 강한 날은 선크림 50+ 재바름 필수!"|
| ────────────────────────────────────────────────────── |
| 🧪 [해커톤 모의 테스트 툴바]                           |
| [ 🏠 귀가 처리하기 ]  [ ☀️ 자외선 강도 변경 (3 -> 8) ] |
| ────────────────────────────────────────────────────── |
| 📋 오늘의 추천 루틴                                    |
|  [x] 1. 미온수로 가벼운 아침 세안                       |
|  [ ] 2. 수분 크림 바르기                               |
|  [ ] 3. 자외선 차단제 (SPF50+) 바르기                   |
|                                                        |
|  [ 🎉 루틴 완료하기 (1/3 완료) ]                        |
+--------------------------------------------------------+

```

#### UI 컴포넌트 & UX 스펙

1. **환경 인지 히어로 카드 (Weather & UV Card)**:
* **UV Index 컬러 배지**: 안전(초록), 보통(노랑), 높음(주황), 매우높음(빨강) 단계별 동적 컬러 적용.
* **상황 가이드 텍스트**: 자외선 지수나 건조도에 따른 1줄 스킨케어 팁 렌더링.
* **갱신 시간 표시**: "1시간 전 갱신됨" + `[🔄 새로고침]` 미니 버튼.


2. **해커톤 전용 모의 시뮬레이터 (Mock Situation Bar)**:
* 화면 상단 고정 Floating/Collapsible 바 형태.
* `[🏠 귀가 모의 입력]` 버튼 클릭 시 Instant Toast / Modal 발송: *"귀가를 감지했습니다! 외출 후 먼지와 선크림을 씻어낼 세안 루틴을 시작할까요?"*


3. **오늘의 루틴 이행 체크리스트 (Interactive Checklist)**:
* **체크박스 애니메이션**: 완료 체크 시 취소선 + confetti/체크 모션 효과.
* **제품 태그 배지**: 각 루틴 카드 옆에 사용할 보유 제품명을 배지로 표시 (예: `[보유제품: A사 수분크림]`).
* **경고 배지 표시**: 취침 전 전용 제품(예: 레티놀, AHA)의 경우 `[🌙 밤 전용]` 배지를 시각적으로 강조.

### 3) 보유 제품 및 사용 주기 관리 (`/products`)

#### 화면 개요

사용자가 현재 보유 중인 스킨케어 화장품을 카드 형태로 관리하고, 특정 성분이나 주기성 케어(진정팩, 니들샷 등)의 스케줄을 등록하는 화면.

```
+--------------------------------------------------------+
| 🧴 나의 스킨케어 화장품 (3개)           [ + 제품 추가 ]|
| ────────────────────────────────────────────────────── |
| +----------------------------------------------------+ |
| | 🌿 B사 레티놀 세럼                       [✏️] [🗑️] | |
| |  • 사용 단계: 에센스/세럼                          | |
| |  • 주 성분: 레티놀 (🌙 밤 전용)                    | |
| |  • 사용 주기: 3일에 1번 (다음 사용일: 오늘 밤)     | |
| |  ⚠️ 주의: 낮시간 사용 금지 (자외선 자극)           | |
| +----------------------------------------------------+ |
|                                                        |
| +----------------------------------------------------+ |
| | 💧 C사 진정 마스크팩                               | |
| |  • 사용 단계: 팩/마스크                            | |
| |  • 사용 주기: 주 2회 (화, 금)                      | |
| +----------------------------------------------------+ |
+--------------------------------------------------------+

```

#### UI 컴포넌트 & UX 스펙

* **제품 등록 / 수정 모달 (Product Modal)**:
* **제품명 입력**: Auto-complete 또는 직접 입력.
* **사용 단계 선택 (Select Dropdown)**: 클렌징, 토너, 에센스/세럼, 크림, 선케어, 마스크팩, 기타.
* **성분/기능 태그 선택 (Multi-select Chips)**: 레티놀, AHA/BHA, 비타민C, 시카, 니들샷 등.
* **성분 감지 안내 시스템 (Smart Badge Notice)**:
* `레티놀` 태그 선택 시 UI 상에 자동 안내문 노출: *"레티놀 성분은 자외선에 민감하므로 자동으로 [밤 루틴]으로 분류됩니다."*


* **사용 주기 설정 (Cycle Picker)**: 매일 / N일에 1번 / 특정 요일 지정 (예: 매주 월, 목).

### 4) 알림 센터 & 웹 푸시 설정 (`/notifications`)

#### 화면 개요

시스템이 자동으로 생성한 **아침 브리핑, 귀가 브리핑, 주기성 케어 리마인더**를 모아보고 완료 여부를 처리하는 화면.

```
+--------------------------------------------------------+
| 🔔 알림 센터                            [전체 읽음]    |
| ────────────────────────────────────────────────────── |
| 📢 웹 푸시 알림을 켜면 귀가 시간에 맞춰 안내를 받아볼 수 있어요.|
|    [ 🔔 웹 푸시 알림 허용하기 ]                         |
| ────────────────────────────────────────────────────── |
| [🏡 귀가 브리핑]                               18:30   |
| "외출 후 귀가하셨군요! 꼼꼼한 2차 세안을 권장합니다."  |
| [ 루틴 확인하러 가기 ]               [ 완료 처리 ]     |
| ────────────────────────────────────────────────────── |
| [☀️ 아침 브리핑]                               08:00   |
| "오늘 자외선 지수가 높습니다. 선크림을 잊지 마세요!"   |
|                                      [ 완료됨 (08:15) ]|
+--------------------------------------------------------+

```

#### UI 컴포넌트 & UX 스펙

1. **웹 푸시 동의 배너 (Push Permission Banner)**:
* 브라우저 권한 미허용 상태일 때 상단에 유도 배너 노출.
* `[알림 허용하기]` 클릭 시 브라우저 네이티브 `Notification.requestPermission()` 호출.
* 거부된 경우: *"브라우저 설정에서 알림을 차단 해제해주시면 꿀피부 루틴 알림을 받을 수 있어요"* 가이드 모달 제공.


2. **알림 카드 리스트 (Notification Card)**:
* **유형별 라벨 배지**: `[☀️ 아침]`, `[🏡 귀가]`, `[🌙 밤/성분]`, `[📅 주기성 케어]`.
* **Quick Action 버튼**: 카드 내에서 바로 `[완료 처리]`, `[나중에 (1시간 뒤)]`, `[닫기]` 인터랙션 지원.
* **이행 완료 시 스태프 UI**: 완료된 알림은 옅은 그레이스케일 처리 및 완료 시각 표시.

## 4. 프론트엔드 상태 관리 및 데이터 처리 전략

본 단원은 **백엔드 API 미완성 또는 해커톤 시연 환경**에서도 프론트엔드가 안정적으로 동작하고, 사용자의 기기 제약 조건 속에서도 알림을 놓치지 않도록 설계된 기술 및 UX 처리 전략이다.

---

### 4.1 Client-side Simulation State (시뮬레이터 상태 관리)

실제 서비스 환경에서는 사용자의 위치(GPS)나 실시간 기상청 API 변경에 의존하지만, **해커톤 시연 시 실시간 이벤트를 즉시 검증하기 위해 Zustand 기반의 클라이언트 시뮬레이터를 구현**한다.

#### 1) 도입 목적

* **시연 편의성**: 발표 중 실제로 외출/귀가를 하거나 시간이 지나지 않아도 **[귀가 모의 입력]** 버튼으로 귀가 세안 알림 팝업 및 루틴 전환을 1초 만에 시연.
* **백엔드 의존성 분리**: 백엔드 API 장애 또는 개발 지연 상황에서도 프론트엔드 단독으로 완벽한 시나리오 테스트 가능.

#### 2) Zustand Store 상태 구조 명세

```typescript
interface SituationState {
  // --- 모의 시뮬레이션 상태 ---
  currentLocationState: 'OUTDOOR' | 'HOME'; // 외출 중 / 귀가 완료
  mockUvIndex: number;                       // 모의 자외선 지수 (0~11+)
  mockWeather: 'CLEAR' | 'RAIN' | 'DRY';      // 모의 날씨

  // --- 시뮬레이션 제어 함수 ---
  triggerReturnHome: () => void;             // 귀가 이벤트 즉시 발생 (알림 팝업 획득)
  setMockUvIndex: (uv: number) => void;      // UV 지수 변경 (대시보드 추천 UI 동적 변경)
  resetSimulation: () => void;               // 초기화
}

```

#### 3) 화면 반영 메커니즘

* 시연자가 UI 상단의 **[🏠 귀가 처리하기]** 버튼을 누르면, `currentLocationState`가 `'HOME'`으로 즉시 전환된다.
* 대시보드 UI는 상태 변경을 감지하여 백엔드 호출 없이 즉시 "귀가 후 세안 루틴 추천 카드가 최상단에 노출"되고 인앱 알림 토스트를 바인딩한다.

---

### 4.2 Web Push API & 3단계 In-App Fallback 흐름

웹 브라우저의 푸시 알림은 사용자의 **권한 거부, iOS Safari 지원 제약, 브라우저 백그라운드 제한** 등 변수가 많다. SkinClock은 이를 대처하기 위해 **3단계 이중 안전장치(Fallback)** 메커니즘을 적용한다.

```
+---------------------------------------------------------------+
|                      1단계: 환경 검수                         |
|   브라우저가 Service Worker 및 Notification API를 지원하는가? |
+---------------------------------------------------------------+
                 │                               │
             (Yes)│                               │(No)
                 ▼                               ▼
+-----------------------------------+   +-----------------------+
|        2단계: 권한 확인           |   |   3단계: Fallback     |
| Notification.permission 상태 검사 |   | 앱 내 알림 센터 드로어|
+-----------------------------------+   | 및 토스트 UI로 대체   |
     │                         │        +-----------------------+
(granted)                   (denied)             ▲
     ▼                         │                 │
+-----------------------+      └─────────────────┘
| OS Native Web Push    | (푸시 불가 시 앱 내 알림으로 안전 전환)
| 상단바/데스크톱 알림  |
+-----------------------+

```

#### 1단계: 브라우저 기능 검수 (Push Support Check)

웹 앱 로드 시 브라우저 호환성을 판별한다.

* `typeof window !== 'undefined' && 'serviceWorker' in navigator && 'Notification' in window`
* 미지원 환경인 경우 푸시 권한 요청 배너를 숨기고 바로 **3단계(앱 내 알림 센터)** 모드로 작동한다.

#### 2단계: 권한 승인 시 - OS Native Web Push (`granted`)

* 사용자가 [알림 허용]을 승인한 경우, Service Worker를 등록하고 푸시 토큰을 백엔드와 동기화한다.
* 아침/귀가/성분 주기 알림 발생 시, 스마트폰 상단바 또는 데스크톱 우측 하단에 **진짜 앱 알림 형태의 OS Native 푸시**를 발송한다.

#### 3단계: 권한 거부(`denied`) 및 미지원 시 - In-App Fallback (앱 내 알림)

* 사용자가 실수로 알림을 거부했거나 푸시 미지원 기기여도 **서비스 이용이 차단되지 않도록 보장**한다.
* **대체 동작 방식**:
1. **인앱 토스트(Toast)**: 사용자가 앱에 접속해 있는 동안 화면 상단에 알림 팝업 노출.
2. **알림 센터 드로어(Notification Drawer)**: 헤더의 `[🔔 알림]` 아이콘에 미읽음 배지(Red Dot)가 표시되며, 클릭 시 우측에서 슬라이드로 알림 목록이 열려 즉시 루틴 [완료 처리]가 가능하도록 지원.

## 6. 비기능적 프론트엔드 요구사항 (Non-Functional Requirements)

### 6.1 반응형 레이아웃 & Touch UI Target

* **Breakpoints**: Mobile First (`< 640px` 메인 최적화, Desktop View는 중앙 모바일 프레임 Shell 또는 확장 레이아웃 지원).
* **Touch Target**: 모든 클릭 가능 버튼 및 체크박스는 최소 **44px × 44px** 이상의 터치 영역 확보.

### 6.2 오프라인 및 데이터 유실 방지 (MVP Persistence)

* H2 DB 리셋 또는 백엔드 재시작에 대비해 사용자가 등록한 온보딩 설정 및 제품 목록 데이터는 1차적으로 **Browser `localStorage` / `IndexedDB`에 동기화**하여 새로고침 시에도 UX가 유지되도록 설계.
