## 1. 프로젝트 개요
---
### 한 줄 정의
SkinClock(스킨클락): 사용자의 생활 상황과 날씨·자외선 정보를 반영해 세안 및 스킨케어 루틴을 안내하는 상황 인지형 알림 서비스

### 제품 목표
스킨케어 초보자가 매일 고정된 시간에 얽매이지 않고 자신의 실제 생활 흐름에 맞춰 세안과 기초 스킨케어를 실천하도록 돕는다. 외출 후 귀가, 날씨, 자외선 정보, 제품 사용 일정 등을 조합해 적절한 시점에 알림을 제공하고, 해당 상황에 맞는 간단한 기본 루틴과 제품 사용 방법을 안내한다.

### 배경
기존 세안·스킨케어 알림 서비스는 사용자가 설정한 고정 시간에만 알림을 제공하는 경우가 많다. 그러나 사용자의 귀가 시간과 일상 패턴은 매일 달라 고정 알림이 실제 행동으로 이어지지 않을 수 있다. SkinClock은 복잡하고 전문적인 피부 관리 시스템보다 일상에 자연스럽게 연결되는 상황 기반 알림과 간단한 루틴 추천을 우선 제공한다. 해커톤 MVP는 웹 프로토타입으로 구현하며, 실제 위치 추적 대신 사용자가 귀가 상황을 모의 입력할 수 있도록 구성한다. 백엔드는 Java 25, Spring Boot 4.1.0, Spring Data JPA, H2 데이터베이스를 기반으로 개발한다.

### 사용자 문제
스킨케어 초보자는 언제 세안하거나 어떤 제품을 사용해야 하는지 판단하기 어렵다. 고정된 시간 알림은 외출·귀가 시간이 달라질 때 맞지 않으며, 날씨와 자외선에 따른 관리 방법이나 제품별 사용 시점을 함께 관리하기도 번거롭다.

### 해결 방안
사용자가 등록한 제품과 기본 루틴을 바탕으로 귀가 상황, 날씨·자외선 정보, 제품 사용 일정 등을 판단해 상황에 맞는 웹 푸시 및 앱 내 알림을 제공한다. 예를 들어 귀가 상황이 감지되면 세안을 권장하고, 자외선이 높은 날에는 자외선 차단 중심의 아침 루틴을 안내하며, 레티놀 등 특정 성분이 포함된 제품은 취침 전 사용하도록 안내한다. MVP에서는 추천 범위를 기본 루틴으로 제한해 이해하기 쉽고 실행 가능한 안내를 제공한다.

### 차별점
단순한 고정 시간 알림이 아니라 사용자의 생활 상황과 환경 정보를 결합해 알림 시점을 유동적으로 제안한다. 또한 복잡한 피부 진단이나 과도한 제품 추천 대신 귀가·날씨·자외선·제품 일정이라는 생활 밀착형 신호를 활용하고, 스킨케어 초보자가 바로 실행할 수 있는 짧은 기본 루틴을 제공한다. 해커톤 MVP에서는 실제 위치 권한과 복잡한 외부 연동 없이 모의 위치 입력으로 핵심 사용자 경험을 빠르게 검증한다.

### 타겟 사용자
스킨케어를 시작했지만 제품 사용 순서와 시점을 체계적으로 관리하지 못하는 18~35세의 스킨케어 초보자. 출퇴근·등하교·외출 등으로 귀가 시간이 매일 달라 고정 알림의 활용도가 낮고, 날씨와 자외선에 맞춰 루틴을 조정하고 싶어 하는 사용자다. 전문적인 피부 지식이 많지 않으며, 긴 설명보다 지금 해야 할 행동과 사용할 제품을 간단히 안내받기를 선호한다.

### 사용자 시나리오
1. 사용자가 웹 서비스에 접속해 기본 세안·스킨케어 루틴과 보유 제품을 등록한다. 제품명, 사용 시점, 성분 태그를 간단한 입력 폼으로 저장한다. 2. 사용자가 외출 후 웹 프로토타입에서 ‘귀가’ 상황을 모의 입력하거나 귀가 이벤트를 선택한다. 3. 시스템은 귀가 상황과 사용자의 루틴을 바탕으로 ‘귀가 후 세안을 권장합니다’와 같은 앱 내 알림 또는 웹 푸시를 발송한다. 4. 사용자가 날씨·자외선 정보를 확인하면 시스템은 해당 환경에 맞춰 기본 루틴을 제안한다. 자외선이 높은 날에는 아침 자외선 차단을 강조하고, 건조한 날에는 보습 중심의 안내를 제공한다. 5. 제품에 레티놀 등 특정 성분 태그가 등록된 경우, 시스템은 해당 제품을 취침 전 사용하는 것이 적절하다는 일정 안내를 제공한다. 6. 사용자는 알림을 완료 처리하고 오늘의 루틴 이행 여부를 확인한다.

### 핵심 지표
핵심 KPI는 다음과 같다. 1) 루틴 알림 완료율: 발송된 알림 중 사용자가 완료 처리한 비율. 2) 알림 반응률: 알림 확인 또는 루틴 화면 진입 비율. 3) 귀가 상황 기반 알림 실행 성공률: 모의 귀가 입력 후 정해진 시간 내 알림이 생성되는 비율. 4) 제품 등록 완료율: 온보딩 사용자가 하나 이상의 제품을 등록하는 비율. 5) 추천 루틴 실행률: 날씨·자외선 추천을 확인한 사용자 중 루틴 완료 처리 비율. 6) 핵심 과업 완료 시간: 첫 접속부터 제품 등록과 첫 알림 확인까지 걸리는 시간. 7) 사용자 만족도: 해커톤 테스트 참가자의 사용 편의성 및 알림 적절성 평가.

### 리스크
1) 웹 브라우저의 위치·푸시 알림 제약으로 실제 귀가 감지가 제한될 수 있다. MVP에서는 모의 위치 입력으로 대체하고 실제 위치 기반 기능과 구분해 표시한다. 2) 날씨·자외선 데이터가 없거나 지연되면 추천 정확도가 떨어질 수 있다. 외부 API 장애 시 사전 정의된 기본값 또는 사용자가 입력한 환경값을 사용한다. 3) 스킨케어 추천이 의학적 조언으로 오해될 수 있다. 질환 진단·치료 표현을 배제하고 일반적인 생활 관리 안내임을 명시한다. 4) 레티놀 등 성분별 권장 사항이 개인 피부 상태와 맞지 않을 수 있다. 성분 안내는 참고용으로 제공하고 사용자의 주의사항 확인을 유도한다. 5) 알림이 지나치게 많으면 피로감과 이탈이 발생할 수 있다. 하루 알림 상한과 중복 알림 방지 규칙을 적용한다. 6) H2 인메모리 데이터베이스는 서버 재시작 시 데이터가 사라질 수 있다. 해커톤 시연 환경에서는 이를 고지하고, 운영 전환 시 영속 데이터베이스를 도입한다.

## 2. 최초 질문지 및 개인 루틴 설정
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자가 최초 실행 시 사용 중인 제품, 피부 타입, 외출 빈도와 시간 또는 불규칙 여부, 기본 스킨케어 루틴을 입력하고 이후 수정할 수 있어야 한다. 이 요구사항은 개인화 추천에 필요한 기본 설정 수집과 관리에 한정하며, 당일 추천 계산과 알림 발송은 포함하지 않는다.

**수용 기준:**
```
1. ○ 사용자는 최초 실행 시 제품, 피부 타입, 외출 패턴, 기본 스킨케어 루틴을 입력할 수 있다.
2. ○ 외출 패턴은 빈도와 시간 또는 불규칙 여부로 설정할 수 있다.
3. ○ 사용자는 저장한 개인 설정과 기본 루틴을 조회하고 수정할 수 있다.
4. ○ 입력한 개인 설정은 일일 추천 생성에 사용할 수 있도록 사용자별로 저장된다.
```


### 2.1 최초 질문지 기반 개인 설정
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 사용자 | **기기**: 웹 브라우저, 모바일 웹 브라우저

최초 이용 사용자가 질문지를 통해 사용 중인 제품명, 피부 타입, 외출 빈도와 시간 또는 불규칙 여부, 기본 스킨케어 루틴을 입력하고 개인 설정을 만들 수 있게 하는 기능이다. 입력 정보는 매일의 개인화 추천과 브리핑 알림의 기준으로 사용하며, 당일 추천 결과를 직접 생성하는 기능은 포함하지 않는다.

사용자가 저장한 피부 타입, 외출 패턴과 기본 스킨케어 루틴을 조회하고 수정할 수 있게 하는 기능이다. 변경된 설정은 다음 일일 추천과 브리핑 알림 생성에 반영하며, 보유 제품과 제품 사용 주기 관리는 별도 기능에서 다룬다.

## 3. 개인화 일일 스킨케어 추천
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

시스템은 사용자의 피부 타입, 외출 패턴, 보유 제품과 사용 주기, 당일 날씨·자외선 정보를 종합해 매일 다른 세안법·권장 제품·스킨케어 루틴을 추천해야 한다. 추천은 일반적인 생활 관리 안내로 제한하며 의학적 진단이나 치료 판단은 포함하지 않는다.

**수용 기준:**
```
1. ○ 시스템은 개인 설정, 보유 제품 및 당일 환경 정보를 함께 반영해 일일 추천을 생성한다.
2. ○ 추천에는 권장 세안법, 사용할 제품 또는 제품군, 루틴 순서가 포함된다.
3. ○ 제품 사용 주기가 도래한 경우 해당 제품의 사용 권장 내용이 추천에 포함된다.
4. ○ 추천 결과에는 일반적인 생활 관리 안내임을 표시한다.
```


### 3.1 개인화 일일 스킨케어 추천
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 사용자 | **기기**: 웹 브라우저, 모바일 웹 브라우저

시스템이 사용자의 피부 타입, 외출 패턴, 보유 제품과 사용 주기, 당일 날씨·자외선 정보를 종합해 매일 다른 세안법·권장 제품·스킨케어 루틴을 제안하는 기능이다. 추천은 일반적인 생활 관리 안내에 한정하며, 질환 진단이나 개인별 치료 판단은 포함하지 않는다.

## 4. 날씨·자외선 정보 시간별 수집·갱신
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

시스템은 외부 API에서 날씨와 자외선 정보를 1시간마다 수집·갱신하여 최신 환경 정보를 개인화 스킨케어 추천의 기준으로 사용해야 한다. 수집 정보에는 추천에 필요한 날씨 상태, 자외선 정보, 정보 기준 시각이 포함되며, 외부 API 장애 시에도 마지막 정상 정보 또는 기본값으로 추천을 제공한다. 이 요구사항은 환경 정보의 수집·표시와 갱신에 한정하며, 환경 정보에 따른 개인화 추천 규칙 자체는 포함하지 않는다.

**수용 기준:**

## 5. 아침·귀가 브리핑 알림
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

시스템은 일일 개인화 추천을 바탕으로 아침 브리핑과 귀가 브리핑 알림을 생성해야 한다. 아침 브리핑은 세안법과 날씨 기반 권장 제품을, 귀가 브리핑은 세안과 저녁 루틴을 안내하며 실제 위치 추적은 포함하지 않는다.

**수용 기준:**
```
1. ○ 아침 브리핑 알림에는 당일 날씨·자외선 정보, 권장 세안법 및 권장 제품 정보가 포함된다.
2. ○ 귀가 브리핑 알림에는 세안 또는 저녁 스킨케어 루틴 안내가 포함된다.
3. ○ 사용자의 외출 패턴 또는 설정된 알림 시간에 따라 각 브리핑 알림을 생성할 수 있다.
4. ○ 동일한 유형의 브리핑 알림이 같은 발송 시점에 중복 생성되지 않는다.
```


### 5.1 아침·귀가 브리핑 알림 생성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 사용자 | **기기**: 웹 브라우저, 모바일 웹 브라우저

시스템이 일일 개인화 추천을 아침 브리핑과 귀가 브리핑 형태로 구성해 발송할 알림을 생성하는 기능이다. 아침에는 날씨·자외선 기반 세안법과 권장 제품을, 귀가 시점에는 세안과 저녁 루틴을 안내하며 실제 위치 추적은 포함하지 않는다.

## 6. 웹 알림 확인 및 루틴 이행 기록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자는 웹 기반 프로토타입에서 아침·귀가 브리핑과 제품 사용 주기 알림을 알림 목록으로 확인하고, 각 알림에 따른 루틴의 이행 상태를 기록할 수 있어야 한다. 브라우저 웹 푸시는 지원 환경과 사용자 권한 허용 시에만 보조적으로 제공하며, 모바일 앱 알림·앱 내 알림·네이티브 앱 기능은 범위에 포함하지 않는다. 이 요구사항은 웹 화면에서의 알림 확인과 이행 상태 기록에 한정하며, 알림 생성 규칙과 추천 내용 산정은 포함하지 않는다.

**수용 기준:**
```
1. ○ 사용자는 웹 브라우저의 알림 목록에서 아침 브리핑, 귀가 브리핑, 제품 사용 주기 알림의 유형·내용·생성 시각을 확인할 수 있다.
2. ○ 브라우저가 웹 푸시를 지원하고 사용자가 알림 권한을 허용한 경우, 새 알림은 웹 푸시로 표시되며 권한 미허용 또는 미지원 환경에서도 웹 알림 목록에서 확인할 수 있다.
3. ○ 사용자는 웹 알림별로 완료, 나중에 확인, 닫힘 상태를 선택해 처리할 수 있으며, 처리 상태는 알림 목록에 반영된다.
4. ○ 완료 처리한 루틴은 날짜, 알림 유형, 처리 시각 및 완료 상태와 함께 사용자별 이행 기록에서 조회할 수 있다.
```


### 6.1 웹 알림 발송 및 추천 이행 기록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 사용자 | **기기**: 웹 브라우저, 모바일 웹 브라우저

사용자가 아침·귀가 브리핑과 제품 사용 주기 알림을 웹 서비스 내 알림 목록 또는 웹 푸시로 받고, 완료 여부를 기록하는 기능이다. 웹 푸시가 지원되지 않거나 권한이 없으면 앱 내 알림 목록을 제공하며, 알림 생성 규칙은 각 알림 기능에서 다룬다.
